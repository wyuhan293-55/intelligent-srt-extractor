# 智能 SRT 字幕提取器 (Intelligent SRT Extractor)

## 概述

版本：1.1.0；作者：Maier Workflow。

与全量转录不同，本 Skill 的核心能力是 **智能筛选**：只转录有信息量的视频，跳过 B-roll / 无声 / 重复内容。

### 核心原则

| 原则 | 说明 |
|------|------|
| **无信息量不转录** | 纯环境音、无声自拍、展示性空镜 → 跳过 |
| **信息过少不转录** | 视频极短（< 3秒）、无对话 → 跳过 |
| **重复内容不转录** | 同一场景多角度重复拍摄 → 跳过 |
| **不确定则提问** | 文件夹名或文件大小无法明确判断 → 列出候选，向用户提问 |

## 工作流程

### 阶段 1：全量扫描

1. 递归列出用户提供的文件夹下所有子目录结构
2. 列出所有视频文件（mp4/mov/mkv/avi/webm 等），标注文件大小
3. 列出所有已有 `.srt` 文件，标记已完成转录的
4. 使用 `scripts/scan_and_classify.py` 可自动完成扫描

```bash
python scripts/scan_and_classify.py "<素材文件夹路径>"
```

### 阶段 2：智能分类

根据 **文件夹名 + 文件大小 + 拍摄设备特征** 判断，以下类型 **默认跳过**：

#### 肯定无信息量（直接跳过，不问用户）

| 类型关键词 | 判断依据 | 原因 |
|-----------|---------|------|
| 开箱 / 拆包 / unbox | 文件夹名包含 | 产品开箱展示，无对话 |
| 自拍 / 氛围感 | 文件夹名包含 | 患者自拍 B-roll |
| 灰底 / 灰背景 / grey | 文件夹名包含 | 标准医学摄影摆拍 |
| 环境 / 病床环境 | 文件夹名包含 | 环境空镜 |
| 等待 | 文件夹名包含 | 等待过程的空镜 |
| 朋友圈 | 文件夹名包含 | 社交平台短视频 |
| 图片 / 照片 / photo | 文件夹名包含 | 拍照过程记录 |
| 术后即刻 | 文件夹名包含 | 术后效果展示 B-roll |
| 合影 | 文件夹名包含 | 合影 B-roll |
| 术中 / 手术过程 | 文件夹名包含 | 手术室无菌环境，常规无对话 |
| Live Photo 短镜头 | 文件 < 5MB | 无声或极短 |
| 短视频 / 微信视频 | 文件 < 3MB | 无信息量 |
| 已有 .srt 且 > 50B | 已有字幕 | 无需重跑 |

#### 不确定的情况（必须向用户提问）

当遇到以下模糊情况时，**收集候选列表，向用户提问**：

- 文件夹名含"画线"但文件很小时 → 可能是特写 B-roll 而非带讲解的画线
- 文件夹名含"换药" → 可能带对话，也可能只是操作过程
- 术后第X天/术后采访 → 可能含回访对话，也可能只是效果拍摄
- 专业相机大文件（>100MB）→ 专业相机有时无声录制
- 文件夹名无明确关键词 → 无法从命名判断

**提问格式**：
```
以下视频无法确定是否有对话信息，请确认是否需要转录：

| 编号 | 路径 | 大小 | 猜测内容 |
|------|------|------|---------|
| 1 | ... | ...MB | 可能是... |
| 2 | ... | ...MB | 可能是... |
```

### 阶段 3：运行转录

仅对确认需要转录的视频运行 Whisper。逐个传入确认的视频路径；目录模式会处理目录下所有待转录视频，不会读取分类结果。

```bash
python scripts/transcribe.py "<确认的视频文件>" --model medium
```

参数说明：
- `--model`：tiny / base / small / medium / large-v3（默认 small）
- `--device`：cuda / cpu（默认 cuda）
- `--engine`：auto / faster-whisper / openai-whisper（默认 auto）

### 阶段 4：质量自检

转录完成后执行：
1. **检查 SRT 文件**：< 50B 的通常是无内容或静音幻觉，需标记
2. **术语修正**：运行 `scripts/fix_terms.py` 检查质量；需要术语修正时，先确认词典适用，再加 `--fix` 修正 Whisper 常见误识别。只修正视频级 SRT，不处理汇总文档
3. **结果汇总**：报告成功/跳过/失败数量

### 阶段 5：案例级 SRT 合并（标准格式）

当用户要求把案例文件夹内的多个 `.srt` "整合成一个总的 srt 文档"时执行本阶段。已有 SRT 可直接合并，无需重跑转录；完成术语修正后再合并。

**推荐用法（显式顺序，由 Agent 按工作流/拍摄时间排序）：**

```bash
python scripts/merge_srt.py --out "<案例文件夹>/{姓名}-字幕汇总.srt" "<输入1.srt>" "<输入2.srt>" ...
```

- 段标题自动取「父文件夹名-文件名（去扩展名）」
- 嵌套子文件夹需要更完整标题时，用 `--titles "标题1|标题2|..."` 按顺序覆盖

**自动扫描用法：**

```bash
python scripts/merge_srt.py --folder "<案例素材文件夹>" --name <姓名>
```

按自然排序合并，输出 `<案例文件夹>/<姓名>-字幕汇总.srt`；自动排序可能不符合工作流顺序，重要案例建议用显式顺序模式。

**标准格式规则（用户确认，严格遵守）：**

1. **段标题行**：每个视频段开头单独一行"文件夹名+视频编号"（如 `术前采访-DE1A0870`），
   嵌套子文件夹时可写完整路径层级（如 `术前术后即刻-术前-5X9A1425`）；标题行不是字幕条目
2. **序号**：各视频的字幕序号独立，从 1 重新开始编号（不要全局连续编号）
3. **时间帧**：保留各视频原始时间戳，**不做累计偏移**，不改动任何数值
4. **文字**：字幕原文原样保留，不加编号前缀、不插标记字幕条、不合并拆分
5. **空行**：标题行与首条字幕之间、各字幕块之间均用空行分隔
6. **编码**：UTF-8（带 BOM）+ CRLF
7. **输出位置**：案例文件夹根目录，命名 `{姓名}-字幕汇总.srt`；覆盖旧版时不留旧文件

**段落排序**：由 Agent 按工作流/拍摄时间顺序判断（术前采访 → 面诊/讲解 → 设计 → 术前即刻 → 术后即刻等），
相机文件按编号顺序，手机文件按文件名时间戳。

**内容过滤**：仅按整条文本匹配跳过 Whisper 幻觉/水印字幕（"字幕by索兰娅""字幕製作人Zither Harp"及单条无意义幻觉如"劇院""滷汁"），
以及空文件；不因正常句子包含“剧院”等词而删除。整段被过滤时不输出空标题。
在最终汇报中说明被排除的文件及原因、部分过滤的条数。解析或读取失败时停止，不覆盖旧汇总；全部为空/被过滤时保留旧汇总。
合并阶段不改写、不删除、不移动原 `.srt` 文件。

---

## 输出规范

- 与源视频 **同名**、**同目录** 的 `.srt` 文件
- 视频级字幕：UTF-8 编码，标准 SRT 格式
- 案例级汇总：UTF-8 BOM + CRLF，带段标题且各段从 1 编号、保留源视频时间帧
- 案例汇总是素材检索文档，不能作为单条视频的连续播放字幕直接导入
